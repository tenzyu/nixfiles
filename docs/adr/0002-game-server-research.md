# Keep one lifecycle owner for Minecraft

Research for [ADR-0002, I-2 and PR2i](0002-invariant-safety.md#delivery-order-and-decision-gates). Reviewed 2026-11-19. The source baseline for the backup is [PR #57](https://github.com/tenzyu/nixfiles/pull/57) at `7f9f23a54f94b31481ebc65e1cddca0bdba1cdf8`. The unchanged input pins are in [main's lock file](https://github.com/tenzyu/nixfiles/blob/0daacae75f19dc2b01712c26471b42b2c6bc9ca3/flake.lock) and the [current lock file](../../flake.lock).

## Recommendation for the parent decision

Retain the pinned `nix-minecraft` guest unit, native container and Tailscale modules, and the local 2g backup adapter. Close 2j as a no-op once the parent approves this disposition. There is no file-level uptake: no new input, package, source file, policy, test, or LICENSE change. Do not add a second lifecycle owner to get a backup command. Tailscale sharing can change who reaches a node, but cannot make a backup safer or replace a service owner.

### The archive is stopped server data, not a system backup

The [2g archive contract](../../modules/50-features/game-servers/_internal/minecraft-backup/README.md) is the baseline for any substitution. The [operator](../../modules/50-features/game-servers/_internal/minecraft-backup/operator.sh) takes the fixed host `flock` after authorization and retains it across `setpriv` and through recovery. It covers cooperating `start`, `stop`, `restart`, `send`, `console`, `exec`, and `backup`; `update` refuses and directs the operator to declarative deployment. A root-only admission guard blocks later managed mutations if a manager job has an unconfirmed outcome. Direct manager calls, timers, background guest payloads, and writes by root or the game UID may bypass the lock. Without evidence that these writers are absent, do not call the archive offline-consistent.

Preflight runs before stopping. A known clean inactive guest stays inactive. The operator refuses a down container, an unreadable unit, or an unknown, failed, or transitional state without starting anything. For a running server, the operator checks the guest unit's clean stop, not an in-game `stop` command or a container state alone. The [writer](../../modules/50-features/game-servers/_internal/minecraft-backup/writer.sh) archives only `survival/` as `27009:27009`, using a private stage in the existing game-owned `/srv/minecraft/backups`. It checks the gzip stream, tar readability, and [member scope and nonempty regular `survival/world/level.dat`](../../modules/50-features/game-servers/_internal/minecraft-backup/archive-checks.py). It syncs the file, links the final name without replacement, and syncs the parent directory. The existing timestamp format stays. A same-second name is a conflict, not permission to replace or prune. This path leaves older archives unchanged. The game UID can still change them separately.

After a verified stop, write, validation, collision, or uncertain publication failures leave the guest stopped. Only confirmed publication permits a previously running unit to resume. A resume failure leaves the published archive intact, reports service failure separately, and returns failure. Inspect the final name and any retained stage before retrying an unknown result. The fixture extracts to an isolated directory; there is no production restore command or automatic extraction over a live world. The `nix-minecraft` stop hook removes tracked managed files, so restore server data under separate authorization and reconstruct declarative settings from Nix. The archive does not restore guest configuration, auth material, or Tailscale identity. Keep those recovery obligations separate.

## Candidate fit

"Fully suitable" means retain an owner for its existing role with the rest of the composition intact. It does not mean the owner implements I-2 alone. "Partial" here means an access option for a separate decision, not code to adopt. Closure comparisons list dependencies and mutable payloads, not byte savings. No alternate closure was built or measured.

| Candidate | Identity, mounts, and lifecycle | World, archives, and recovery | Reproducibility, upkeep, authority, and cost | Disposition |
| --- | --- | --- | --- | --- |
| Pinned `nix-minecraft` | Existing guest unit fits the container, numeric IDs, mounts, and TUN. NixOS owns the container and `tailscaled`; 2g owns managed-operation coordination. | No independent archive lifecycle. Keep the offline capture and no-replace writer in 2g. Declarative files come back through Nix. | Root-locked module and overlay, pinned Fabric and Java, tmux and small file/config helpers already selected. No new software or service fee proposed. Existing Mojang EULA boundary stays. | **Fully suitable for the existing guest-unit role.** Retain; do not extract files. |

Adding it beside the current unit would add a second owner and could compete for the world and port. | No equivalent archive or state/restart checks. Override the directory to point at the current world and 2g still addresses the wrong unit; its console transport and managed-file assumptions also change. | Removes the overlay only if the Fabric package is replaced too. The native default is hash-pinned vanilla, not this Fabric deployment. Native package override alone saves no demonstrated closure. Same game EULA, no paid manager. | **Reject as a replacement or companion.** |

Requires authorized action and acceptance on both sides. | **Partial for access only.** No change in 2j. |

## Implementation and license evidence

### The two Nix modules do not own the same unit

`flake.lock` resolves `nodes[root].inputs["nix-minecraft"]` to [`2191fbfdcd90817e5e814182635533b5a750590d`](https://github.com/Infinidoge/nix-minecraft/commit/2191fbfdcd90817e5e814182635533b5a750590d), a 2026-11-17 lock update, with no tagged release observed. Its `nixpkgs` input follows the root input. The [flake exports](https://github.com/Infinidoge/nix-minecraft/blob/2191fbfdcd90817e5e814182635533b5a750590d/flake.nix#L35-L55) and [Fabric recipe](https://github.com/Infinidoge/nix-minecraft/blob/2191fbfdcd90817e5e814182635533b5a750590d/pkgs/fabric-servers/default.nix) select locked game and loader data. The [launcher](https://github.com/Infinidoge/nix-minecraft/blob/2191fbfdcd90817e5e814182635533b5a750590d/pkgs/build-support/mkTextileServer.nix) joins the vanilla jar, Fabric loader, and Java. The module's [management hooks](https://github.com/Infinidoge/nix-minecraft/blob/2191fbfdcd90817e5e814182635533b5a750590d/modules/minecraft-servers.nix#L149-L216) start and stop the tmux session inside the guest unit. ### Sharing requires its own approval

The guest uses the [root-pinned native Tailscale module](https://github.com/NixOS/nixpkgs/blob/f68407657ad294471eb4b2e65d193df26edf729f/nixos/modules/services/networking/tailscale.nix) and its [package recipe](https://github.com/NixOS/nixpkgs/blob/f68407657ad294471eb4b2e65d193df26edf729f/pkgs/by-name/ta/tailscale/package.nix), client `1.104.5` at [`73a48057aaf5f60e4f770b398e9b7af576b01dbe`](https://github.com/tailscale/tailscale/commit/73a48057aaf5f60e4f770b398e9b7af576b01dbe), with Nixpkgs patches. The upstream client [BSD-3-Clause license](https://github.com/tailscale/tailscale/blob/73a48057aaf5f60e4f770b398e9b7af576b01dbe/LICENSE) credits Tailscale Inc & contributors (2020); it is not a license for the hosted sharing service. The hosted implementations are not pinned by the client version. The operative evidence is the official feature docs, pricing, and terms checked on 2026-11-19.

- [Link-based sharing](https://tailscale.com/docs/features/sharing), last validated 2026-01-05, is beta on all plans. An Owner, Admin, or IT admin on the sharing tailnet issues the invitation. The individual recipient accepts and must have one of those roles on the receiving tailnet. The share is visible to that recipient, not their entire tailnet; tagged peers on the receiving tailnet cannot use it. Both tailnets' access policies apply. A shared node is quarantined by default and does not advertise its subnets to the other tailnet. For any later approval, scope specific identities to the Minecraft port and check invite, acceptance, and revocation separately. The [pricing page](https://tailscale.com/pricing) lists the Personal plan at $0; this is not approval to change any plan or an account-specific billing quote.
- [Declarative node sharing](https://tailscale.com/docs/features/declarative-node-sharing), last validated 2026-08-26, is alpha under Feature previews. Both trusted tailnet admins must opt in. The receiving policy lists groups or tags the sharing tailnet may reference, and the sharing policy accepts incoming connections from that tailnet and grants access to selected local resources. There is no per-user invitation. The documented limits are three external tailnets and 500 nodes per participating tailnet. Subnet advertisements, tailnet services, and exit nodes are not supported in this mode. The feature page and pricing page do not establish an entitlement or fee for specific accounts. The pricing page's “Multiple tailnets” add-on is a different offering, not proof of a sharing charge. Do not assume the alpha is generally available, free, or covered by a production SLA.
- The [Terms of Service](https://tailscale.com/terms) updated 2026-08-25 distinguish hosted service, plans, and preview or evaluation availability from open-source code. Sections 2.4, 2.8, 3, and 13.1 cover customer permissions and consents, voluntary research with no promise of general release, paid fees, and evaluation limits. The [Special Terms](https://tailscale.com/special-terms) apply where relevant. No plan, separate agreement, counterparty consent, or active share was inspected or inferred. Any future change needs both parties' authorization and a fresh check of eligibility, terms, and cost.

## Verification and limits

- **2g packaged-test acceptance, not deployment.** At the exact #57 head, `nix eval --raw .#checks.x86_64-linux.game-backup-minecraft.drvPath` selected `4kd0l08gqm7294g53rla6rrs5jys3gw6-game-backup-minecraft-tests.drv`. The existing output was valid and `nix log .#checks.x86_64-linux.game-backup-minecraft` recorded the packaged restore, numeric ownership, same-second collision, state refusals, injected failures, separate resume outcome, and descriptor contention cases. The [fixture](../../modules/50-features/game-servers/_internal/minecraft-backup/test.nix) uses inert managers and mocks the UID transition by default. #57 also reports a separate private-namespace run with the real `setpriv` and inert managers. These are designed acceptance tests for 2g, not live recovery, writer exclusion, or power-loss evidence.
- **2i evaluation and source inspection.** Evaluated the `neko7` toplevel derivation and selected container, guest service, package and operator fields, and evaluated the root-pinned native module in a separate in-memory NixOS configuration. No game or Tailscale process was started or queried. LinuxGSM, ALH477's module and VM, upstream Minecraft tests, and sharing behavior were not executed. No production data, credentials, accounts, shares, or fees changed, and #57's merge and host acceptance are separate. Host acceptance would still need a dated, authorized check of the native wrapper and lock, actual clean-stop evidence, the destination filesystem, absence of bypass writers, and recovery.
- **2j re-entry.** Reopen only for a specific unmet need and a candidate that removes an existing responsibility without duplicating lifecycle or weakening I-2. Any approved substitution must compare the evaluated guest unit, mounts, numeric ownership, Fabric world path, and unchanged backup leaves. Rerun the packaged 2g contention, fault, and isolated restore fixtures against the changed composition before asking for separate host acceptance.

Upstream source links name inspected commits. Repository-relative contract links follow the landed files after the stack is squashed. #57 identifies the receipt rather than serving as an immutable blob link to a disposable branch commit.
