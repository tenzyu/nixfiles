The two-host control test is opt-in. Set `SPLITCAST_TEST_SSH_HOST`, `SPLITCAST_TEST_SSH_IDENTITY`, and `SPLITCAST_TEST_REMOTE_PYTHON`, then run `PYTHONPATH=packages/splitcast:packages/splitcast/tests python -m unittest test_ssh_twohost -v`. The identity must already authenticate to the test host. The test uses temporary local files and a temporary remote loopback server.

The isolated display and audio launcher is `scripts/splitcast/isolated-obs-test.sh`. Run it inside `dbus-run-session` with the dependencies and environment required by `test_live_devices.py`. Its runtime logs remain under `/tmp/opencode`; it terminates only the processes it started. One earlier full live-device run failed during the second OBS scene setup, while an isolated rerun of that test passed. The failure cause is not established.

The neko7 toplevel build and earlier synthetic tests are described in the handoff and linked evidence. OAuth refresh has not been tested against Twitch. Real local recording recovery passed once in Xvfb but remains intermittent. Automatic Twitch output recovery is not implemented. SSH child recovery has not been tested over the real two-host media path. These limitations remain acceptance blockers.
