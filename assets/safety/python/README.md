# Private Python safety operations

The Linux module has one executable intent, `MoveNew`. The Home adapter uses it to move legacy regular files or directories and archive an existing destination directory under migration state. The same intent can publish a regular backup from a private stage. It uses the Linux no-replace flag with two authorized parent descriptors and flushes their directory entries after the move.

The caller opens and authorizes both parent directories, selects the exact leaves and source type, and records the approved effective UID in the frozen intent. Use open, sync-capable directory descriptors and hold them through execution. Intent construction reads descriptor metadata only. For mutation, the caller passes `confirmed=True` only after explicit authorization for that intent. The Home adapter owns manifest policy, batch preflight, opening and creating parents, locks if appropriate, and its existing journal.

- `Leaf` accepts one relative component. Absolute names, traversal, embedded separators, NULs, and non-directory descriptors are refused. Parent resolution, including symlink policy, belongs to the caller. A selected directory remains the target if moved after opening. The descriptor establishes neither current pathname ancestry nor leaf identity.
- `execute_move` checks the source type without following a source symlink and uses `renameat2(RENAME_NOREPLACE)`. The source parent and leaf must be protected against substitution for as long as the caller relies on a specific type or object. The source type check and rename are separate operations. The destination may have competing creators. A competing regular file, any symlink, or a directory at the final leaf causes a conflict without altering it. Cross-mount or unsupported renames have no fallback.
- For a new regular backup, the adapter creates, writes, validates, and flushes the stage file under a private parent on the destination filesystem, with a retained file descriptor. It must control the stage name until the rename. A successful rename consumes that name. The core flushes the destination parent and then the source parent if distinct. It does not flush payloads or ancestors of newly created directories.
- `Conflict` and `Unsupported` retain the kernel errno when present. Other I/O failures propagate or are chained to `OutcomeUnknown` if the rename may have taken effect. On an interrupted syscall or failed parent flush, inspect both leaves and the caller's journal before retrying. A SIGKILL can leave an ambiguous state without a Python exception. Stage cleanup and recovery belong to the adapter. Existing-entry replacement and unlink require their own writer and ownership decisions.

`checks.x86_64-linux.safety-python` imports the same Nix-packaged module a later adapter can use. Fixtures use isolated directories and observe inode, mode, content and link targets. They exercise `INTENT-01`, `BOUNDARY-01`, `PUBLISH-01`, `PUBLISH-02`, and `RECOVERY-01` at the rename and parent-flush boundaries. The second-filesystem case reports a skip when writable `/dev/shm` on a distinct device is unavailable. Injected errors and an interrupt exercise recovery reporting. The flush sequence is fixture evidence, without a power-loss test. A pinned Bash and GNU `ln -T` compete with Python at the same final leaf without any dependency on the Shell core. Shared locking and packaged Shell-core interoperability can be assessed at convergence.
